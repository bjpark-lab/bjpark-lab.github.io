# SSIT 전술판 배치 검수 기록

검수일: 2026-11-24

## 검수 범위
- 총 15개 전술, 62개 도면 및 단계
- PPT에서 옮겨 온 전술 9개는 **원본 도면별 정적 스냅샷**
- 상세 HTML 기반 전술 6개는 **시간순 단계와 마무리 선택지**
- SSIT 원본 PPT 파싱 자료: `ssit/patterns-2026.json` (복구)
- 상세 원본 전술판: `ssit/original/` (유지)

## 수정한 문제
1. 베이스 패턴 / 엘리베이터: 1번은 엔드라인 밖 인바운더. 선수 표시를 화면 안에 보이도록 보정하면서 코트 밖 위치 유지
2. 사이드 패턴: 인바운더가 좌측 화면 끝에서 잘리는 문제 수정
3. 혼즈 스윙 / 혼즈 줌 / 5-Out: 서로 다른 PPT 도면 간 선수를 강제로 보간하지 않도록 수정. 비연속 구도를 실제 이동처럼 보여주지 않음
4. 원본 PPT의 공 위치: 특정 선수 소유로 임의 지정하지 않고 도면의 실제 공 좌표를 독립 마커로 표시
5. 혼즈 핀다운: 양 코너 3점 위치 및 우측 스크리너 위치 수정
6. 혼즈 업 / 플레어: 백스크린·플레어 스크린 준비 위치와 방향 보정
7. 포스트 플레어: 2·4번 표시 겹침 제거, 반대편 코너 위치 보정
8. 스플릿 / L 패턴: 스크리너가 컷한 다음에도 스크린 표시가 잘못 따라가는 문제를 고정 좌표 `screenAt`으로 해결
9. SSIT 원본 자료 404: 옛 `patterns-2026.json` 복구 후 링크 연결
10. 코트·선수 사이 간격, 인바운더 예외, 코너 3점, 옵션 분기, 원본 파일 존재 여부 검사 추가

## 기하 기준
- 공격 골대 위쪽, 하프코트 내부 가로 500, 세로 510, FIBA 비례
- 공격수 중심 간 34 미만이면 표시 겹침으로 검사 실패
- 코너를 명시한 초기 배치는 x≤30 또는 x≥470 기준
- 인바운더는 코트 밖 배치 허용. 다만 화면 viewBox 안에서 보이도록 제한
- 원본 PPT 도면의 각 단계는 반드시 원본 표시 화살표와 공 좌표 보존

## 한계
PPT 도면은 움직임의 정지 화면입니다. 모든 화살표가 같은 순간에 일어난다거나 각 도면이 시간적으로 이어진다고 단정하지 않았습니다.
상세 HTML로 만든 여섯 전술은 핵심 세팅을 통일했지만 원본 특수 옵션, 커브 동선, 미세한 타이밍을 전부 동일하게 복제한 것은 아닙니다. 필요하면 각 전술의 `기존 상세 애니메이션` 링크로 비교해야 합니다.


## 추가 검수: 빠진 스크린 표시 (2026-11-24)

기존 상세 전술 6개는 스크린 마커가 있었으나, 원본 PPT 기반 9개는 `screen` 정보가 전혀 없었습니다. 코트의 선수·공 위치와 PPT의 원본 화살표를 유지하면서 아래 **4개 전술**에 스크리너 표기를 추가했습니다.

| 전술 | 마커를 추가한 도면 | 표시 내용 |
|---|---|---|
| 혼즈 줌 | 도면 1 | 4번 → 2번 핀다운 |
| 혼즈 줌 | 도면 2 | 3번 → 2번 DHO(패스하면서 스크린) |
| 엘리베이터 | 도면 1·2 | 4번, 5번 스크린 |
| 혼즈 다운 | 도면 1·2 | 4번, 5번 다운스크린 |
| 스페인 픽앤롤 | 도면 2 | 5번 → 1번 온볼 스크린 |
| 스페인 픽앤롤 | 도면 3 | 2번 → 5번 롤맨 수비 백스크린 |

스크린은 보라색 막대와 선수·대상 라벨로 표시됩니다. `screenLabels`와 `screenAngles`로 통합 렌더러에서 그리며, 기존 SSIT 원본 PPT 스냅샷은 연결 동작으로 보간하지 않습니다.

**확정 불가:** 베이스 패턴, 혼즈 스윙, 사이드 패턴, 5-Out 옵션 1·2는 원본 도면만으로 누가 스크린을 걸었는지 확정할 수 없습니다. 일부 화면에는 2대2 패턴이나 컷이 있지만 스크리너를 추정해 그리면 실제 팀 약속과 달라질 위험이 있어 표시를 보류했습니다. 신규 스크린 막대는 원본에 직접 그려진 도형이 아니라 전술 개념을 설명하기 위해 보완한 표시입니다.

관련 검사: `basketball/tests/validate-ssit-geometry.cjs`에서 스크린 마커·설명·방향과 불확실 전술의 미표기를 점검하며, `browser-smoke.cjs`에서 공개 사이트의 해당 단계 DOM과 실제 전술판 캡처를 확인합니다.


## 스크린 접점 및 라벨 위치 재설계 (2026-11-24)
SSIT와 MORE 공통으로 스크린 61개 모두 스크리너 → 스크린을 받는 선수 관계를 지정했습니다.
- 스크린 보라색 막대: 두 선수의 연결 방향에 수직으로 놓고, 스크리너에서 상대를 향하는 쪽에 표시
- 설명 라벨: 두 선수 중간점에서 출발해 유니폼 표시를 가리지 않는 가장 가까운 위치로 조정
- 밀집된 위치에는 얇은 보조선을 넣어 라벨과 접점을 연결
- 좌우 반전, SVG 저장, PC·모바일 모두 공통 적용
- 화면에 보이는 현 위치와 이미 완료한 스크린 접점이 다른 경우에는 `screenAt`, `screenTargetAt`으로 과거 접촉 지점 표시
- `basketball/tests/validate-screen-layout.cjs`로 두 팀 61개 마커×좌우반전을 검증하고, 공개 브라우저에서 화면별 보라 막대, 라벨, 접점 좌표를 추가 검사


## 실제 접점 재검수
원본 PPT의 화살촉 없는 선 11개를 이동 화살표에서 분리해 원본 스크린 접점으로 복원. 베이스, 엘리베이터, 혼즈 다운, 스페인 픽앤롤, 혼즈 줌, 사이드 패턴에 적용. 스페인 온볼/백스크린 단계 수정. DHO는 원본에 접점 선이 없어 점선 예시로 표시. 상세 전술은 컷 출발 방향과 스크린 접점의 관계를 별도 기록했으며, 원본 영상과 일치하는지 추가 확인이 필요합니다.


## 혼즈 업 원본 두 버전 분리 (2026-11-25)
PPT 3번의 Horn UP(2·3번 엘보, 4·5번 코너)을 별도 `horn-up-ppt` 항목으로 복원했습니다. 원본 2개 도면의 선수·공 위치와 화살표를 과거 변환 데이터에서 그대로 가져왔습니다. 기존 HTML 버전(엘보 패스 후 1번 백스크린)은 기존 ID `horn-up`와 7단계 동작을 유지합니다. 메뉴에서 각각 혼즈 업 (PPT), 혼즈 업 (HTML)로 구분합니다. 현재 SSIT 총 16개, 64단계(원본 PPT 10개/25도면, 상세 HTML 6개/39단계)입니다.
