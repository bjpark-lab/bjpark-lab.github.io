4. Agent-ready Data

Agent Serving DB = Agent-ready Data

AI가 아니라 특히 Agent가 빠르고 안전하게 질의할 수 있도록 준비된 데이터 계층.

Raw / Curated

원천 테이블 통합, 식별자 정규화, 품질 검증, 시간축 정리

RecipeMetrologyFDCEquipment

Agent-ready

질문에 바로 답하기 좋은 grain과 summary / context / evidence 중심 schema

lot_contextrecipe_changechamber_summarymetrology_trend
예: LOT × Chamber × Recipe × Metrology × FDC summary → Agent가 수억 row raw table을 직접 뒤지지 않아도 됨 → lineage / freshness / quality / access policy를 함께 관리
AI-ready의 하위 개념으로 Agent-ready를 명확히 정의05
5. Process Data vs Process Core

책임을 분리하면 유지보수가 쉬워짐

Process Data

“데이터를 어떻게 가져올 것인가?”

•
Agent-ready DB 조회
•
ClickHouse / Impala / Parquet adapter
•
Schema normalization
•
기간·row·bytes·timeout 제한
•
Query policy / cache / access control

Process Core

“가져온 데이터로 무엇을 판단할 것인가?”

•
Recipe diff / Step alignment
•
Chamber effect / matching
•
Metrology shift / SPC / trend
•
FDC anomaly / evidence 생성
•
Root cause candidate ranking
LLM이 계산하게 하지 말고, Process Core가 계산하고 LLM은 계획·해석·설명하게 함.
DB 기술과 공정 판단 로직을 분리06
