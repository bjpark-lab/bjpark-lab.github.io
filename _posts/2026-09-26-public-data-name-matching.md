공공 데이터의 대상 이름과 민간 서비스의 이름이 다를 때, **언제 같은 대상이라고 판정하고 언제 판단을 보류해야 할까?** 제 답은 이름이 비슷하다는 이유만으로 연결하지 말자는 것입니다. 잘못 이어진 한 건이 이후 집계의 기준 키를 바꿔 버리기 때문입니다. 이 글은 특정 거래나 시세가 아니라, 코드에 나타난 매칭 설계와 그 한계를 살펴봅니다.

## 오매칭은 단순한 누락보다 발견하기 어렵다

예를 들어 합성 데이터에서 공공 데이터의 `푸른마을 1단지`를 민간 데이터의 `푸른마을 10단지`에 붙였다고 해 봅시다. 이름의 앞부분만 비교하면 그럴듯해 보이지만 두 대상은 다릅니다. 이후 단지별·면적별로 두 데이터를 묶는다면 한 단지의 기록을 다른 단지의 매물과 비교하는 결과가 나옵니다. 연결에 실패해 결과가 비는 경우와 달리, 오매칭은 완성된 수치처럼 보이므로 검토자가 놓치기 쉽습니다. 여기서 단지명은 설명용 가상 이름이며 실제 관측값이 아닙니다.

실제로 확인한 프로젝트 코드에서는 공공 실거래 응답의 `aptNm`을 `apt_name`으로 읽고, 관심 대상의 이름·동·별칭과 `_match_complex`로 대조합니다. 이 함수는 이름의 공백과 일부 일반 단어를 정리하고, 양쪽에 숫자 토큰이 있는데 공통 숫자가 없으면 후보를 건너뜁니다. 테스트에도 이름의 숫자 접두만 일치하는 경우를 거부하는 사례가 있습니다. 숫자를 무조건 지워서 이름을 단순화하면 안 되는 이유입니다.

## 정규화는 후보를 찾고, 수동 매핑은 동일성을 확정한다

정규화에는 공백 제거, 대소문자 통일, 괄호 표기의 분리처럼 표면적인 차이를 다루는 작업을 맡기는 편이 안전합니다. 반면 `푸른마을`이라는 짧은 이름만으로 어느 대상을 가리키는지 결정하는 일은 정규화가 해결하지 못합니다. 동·식별번호·단지 차수처럼 구별에 필요한 정보를 후보 평가에 남겨 둬야 합니다. 확인한 구현은 동이 같은 후보를 앞에 놓지만, 다른 동 후보를 목록에서 완전히 제외하지는 않습니다. 따라서 동 우선순위를 **동 일치 보증**으로 읽으면 안 됩니다.

수동 매핑 테이블은 자동 규칙이 판별하기 어려운 표기를 검증된 식별자에 연결하는 곳으로 두고 싶습니다. 원문 이름, 출처, 지역 식별자, 확정된 대상 ID, 근거와 검토 시점을 함께 기록하면 나중에 규칙을 바꿔도 판단을 재검토할 수 있습니다. 이 테이블은 현재 코드에 구현돼 있다는 설명이 아니라 **개선 제안**입니다. 확인한 코드는 관심 대상 설정에 있는 `aliases`를 매칭에 사용하고, 짧은 별칭에는 정확 일치만 허용하지만, 별도의 검토 이력이 달린 매핑 테이블까지 확인되지는 않았습니다.

## 매칭 실패와 애매함을 결과의 일부로 만든다

현재 수집 루프는 `_match_complex`가 식별자를 돌려준 거래만 저장하고, 일치하지 않는 항목은 저장 경로에서 건너뜁니다. 반환 요약에는 삽입 건수와 API 호출 오류 등이 담기지만, 미매칭 건수나 보류 사유는 없습니다. 그래서 삽입 건수만 보고 데이터가 충분히 수집됐다고 결론 내리기 어렵습니다. API 호출 실패는 예외로 구분하는 설계와 별도로, **호출은 성공했으나 연결하지 못한 항목**도 관측할 필요가 있습니다.

개선한다면 원본 식별값은 별도 보존하고, 처리 결과를 `확정 / 후보 복수 / 후보 없음 / 규칙 거부`처럼 구분해 건수와 사유를 기록하겠습니다. 후보가 여럿이면 첫 번째를 자동 채택하기보다 검토 큐로 보내고, 새 규칙을 배포할 때는 이전 판정과 달라진 항목을 비교합니다. 개인정보나 거래 세부값 없이도 원문 표기·지역 키를 안전한 범위에서 다루고, 운영 리포트에는 집계만 노출할 수 있습니다. 이것은 현행 구현의 기능이 아니라 다음 설계 단계에 대한 제안입니다.

결국 이름 매칭의 품질은 얼마나 많이 붙였는지가 아니라, **잘못 붙일 가능성을 얼마나 가시화하고 멈출 수 있는지**로 평가해야 합니다. 구현 근거: 프로젝트의 `collectors/molit_api.py`에 있는 `_match_complex`와 `collect_transactions`, `tests/test_molit_matching.py`의 숫자·별칭 회귀 테스트, `analysis/compare.py`의 단지 식별자와 면적 구간별 집계 코드. 원본 데이터나 실제 비교 결과는 이 글에 사용하지 않았습니다.
